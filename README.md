# 生活實驗室

收錄生活主題的練習作品。首頁採用「生活誌」精簡版：暖白與墨綠、襯線字、純文字專案目錄與 CSS 製作的筆記本小插畫；標題區與整體留白保持精簡。亮暗兩版支援手機與桌面。首頁與所有專案點子本共用 `assets/journal.css`，保持同一套暖白、墨綠、襯線字與細分隔線風格。

- `/`：生活實驗室作品首頁。
- `/home-buying/`：購屋紅綠燈，保留完整的建案觀察、開價判讀、趨勢分析與看屋筆記。
- `/home-buying/notes.html`：購屋作品的方向與點子本，與看屋筆記分開。
- `/investment/`：投資發大財，資產配置再平衡、固定報酬情境模擬與手動期權策略工具。
- `/investment/notes.html`：投資專案點子本，沿用原筆記儲存鍵與內容。
- `/english/`：一天一英文，規劃中的英文學習主題與點子本。
- `/reading/`：翻頁之後，規劃中的讀書心得主題與點子本。

首次進站依裝置的亮暗偏好顯示，手動切換後會記住選擇，並在各入口間共用。購屋作品沿用原有的瀏覽器儲存鍵，因此同一網址來源下的既有觀察列表與筆記仍可讀取。購屋的程式、資料與測試保留在原有位置，資料網址依模組位置解析，支援部署在子路徑。

## 規劃中的專案點子本

首頁每個專案右側皆有獨立的筆記圖示。投資的筆記入口已獨立為 `/investment/notes.html`；英文與閱讀入口，以及購屋專案的筆記入口，都可編輯「方向與目標」，並在「點子與靈感」用輸入框搭配「＋」或 Enter 新增，逐則編輯、勾選完成與刪除；本次頁面中最後刪除的點子可按「復原」找回。標題與點子總數在同一行；列表採緊湊的 checkbox 工具版面，沒有排序控制與編號。所有修改和尚未加入的輸入草稿都會自動儲存，也可手動儲存或下載 checkbox Markdown 備份。勾選狀態會保留，點子仍維持原位置。

每個專案使用獨立的 `life-lab-project-notes-v2:<project>` 儲存鍵。首次開啟若只有舊版 `life-lab-project-notes-v1:<project>` 筆記，會依換行轉為條列；保留原有方向與各行文字，並保留舊版原始儲存值。既有條列資料缺少完成狀態時會預設為未勾選，並保留原文字及位置。新版格式無法讀取時不會用舊版覆蓋它，仍提供原始備份。

筆記只存在目前瀏覽器的同一個網址來源，不會跨裝置同步。本機預覽與 GitHub Pages 是不同來源；網站程式發布時不會帶走瀏覽器裡的筆記，可下載備份後複製文字到另一個來源。若瀏覽器拒絕儲存或容量不足，頁面會提示下載備份；既有筆記格式無法讀取時會保留原始資料並提供原始備份。

發布規則：只有使用者明確說「更新至 GitHub」後，才推送本機變更與發布。

## 投資發大財工具包

沿用首頁的暖白／墨綠亮暗版，以 A 配置與 B 期權頁籤切換。`assets/investment/portfolio.mjs` 與 `options.mjs` 都是純計算模組；網頁直接呼叫函式，不需要 HTTP API 或後端。首頁主要入口開啟工具，右側筆記 icon 開啟獨立點子本。

### A 資產配置再平衡與情境模擬

- 使用者可編輯組合、現金、每月投入、商品原交易幣別、TWD 市值、商品內部目標比例及情境年化報酬，並新增、刪除與復原商品。預設為討論中的 70／30、每月投入 10,000 元、5 個百分點門檻及 VOO／BTC／0050 範例。
- `previewRebalance(input)` 對應 A-3 JSON：總投資／總資產與目標的絕對偏離嚴格大於門檻才觸發。商品內部偏離不會獨立觸發；始終提供回到精確目標的理論明細，未觸發時 `suggested_total_trade` 為 0、`suggested_trades` 為空。交易以 TWD 金額表示，尚未換算交易股數。淨買賣與總買進／總賣出分開顯示，避免誤認商品間的對沖交易。
- `previewContribution(input, amount)` 將新資金先列入現金，以投入後總資產計算目標。只使用本次新增資金，最多買進至總投資缺口，再按各商品正缺口分攤；剩餘留作現金，不會為了投入而賣出。正常 70／30 新增一萬元即買進七千、留下三千。若仍超過門檻，另外標示既有資金仍需再平衡；此預覽不改寫目前持倉。
- `simulatePortfolio(input)` 對應 A-4：第 0 月依目標配置初始化，使用 `(1 + annual_return) ** (1 / 12)` 的有效月複利因子；每月先計算報酬、月底加入新資金並分配，再檢查門檻。觸發時回到精確的投資、現金與各商品目標，買賣不增加總資產。支援 5／10／20 年 UI 選項（匯入 1–50 年亦支援），折線圖、逐年表及逐月 CSV。
- 金額以 BigInt 整數 TWD 分計算，比例以十億分之一儲存；有效月因子量化為 12 位小數，每月金額四捨五入。目標與新增資金分配採最大餘數法，確保分攤總和守恆。總資產、累積投入本金、損益與現金比例逐月分開記錄。總資產歸零時現金比例為 `null`，顯示「—」。
- 所有 TWD 輸入欄位顯示千分位逗號，右側原生上下箭頭以一千元增減；其他數值欄位統一箭頭樣式並保留原步進。計算、儲存及 JSON 匯出使用不含逗號的數值。
- 比例合計、金額精度、非負數、重複商品、基準幣別及支援模式均驗證。不含真實報價、匯率、費稅、波動模型或自動交易；固定年化報酬均為使用者情境假設。

### B 手動期權策略

- 訊號可選 Nasdaq-100（NDX）或 QQQ，期間 20／60／252 個交易日，預選 60；預選觀察 NDX、回落 3%。進場商品固定為標準 QQQ Call。切換觀察標的時會清空該標的報價與歷史資料，避免混用。
- 高點可手動輸入並清楚標為期間未驗證；也可匯入 `date,close` CSV，取報價美東日期之前最近 N 筆收盤資料的高點，拒絕日期重複、週末、無效價格與資料不足。CSV 必須由使用者確認交易日資料完整及價格口徑一致，工具不補齊缺漏或自動抓行情。
- 報價與時間手動輸入，本頁按檢查才比對條件；超過 15 分鐘標為待更新。同一組標的／期間／門檻在價格回到門檻以上後才重設回落提醒。頁面關閉不會排程或推播。
- 約 90 個曆日、價外 5% 的日期／履約價只提供合約搜尋參考，不假造掛牌期權鏈。
- 持倉手動輸入口數、履約價、到期日、平均買入與目前每股權利金及報價時間，顯示 +100% 停利與 -30% 停損（可編輯）、USD 成本與損益、到期日提醒。以標準 100 股乘數計算；一口不能平倉一半，奇數口數的向下取整僅供確認。剩餘部位出場規則須自行決定。停損提醒不保證成交價，也不會送單。

### 工具儲存與備份

工具使用獨立的 `life-lab-investment-toolkit-v1`，包含尚未完成的表單草稿、期權觀察資料及提醒紀錄。設定修改後自動儲存，可匯入／匯出完整配置 JSON，亦可下載／還原包含兩個工具的完整備份。匯入與重設會先確認取代，既有專案筆記儲存鍵不變。損壞或不支援的工具資料不會被範例覆蓋，提供原始下載；儲存失敗時提示下載備份並保留畫面輸入。資料僅限同一瀏覽器與來源，無跨裝置同步。

`test/investment-portfolio.test.mjs` 包含 A–E 驗收、門檻邊界、商品內部偏離、新資金分配、整數分攤、逐月本金／損益守恆、有效月複利與負報酬／歸零案例。`test/investment-options.test.mjs` 驗證期間、高點計算、時間、權利金停利停損、口數與到期條件。

## 購屋紅綠燈：中和區預售屋試行版

搜尋中和區已有公開成交紀錄的預售建案，輸入房屋坪數與每坪開價，再從候選清單加入至少三個不同建案，查看紅黃綠燈與各案成交基準。

頁面下方也可自行建立「我的建案觀察列表」。每個建案顯示最新一筆成交單價與日期、近三年平均成交單價／總價／房屋坪數，以及便宜、合理、昂貴三個參考價。列表保存在目前瀏覽器的 Local Storage。

第三頁簽「AI 趨勢分析」可選建案，檢視近三年各年度成交單價中位數與官方捷運工程線索。年度變動僅在兩個年度各有至少 5 筆成交時顯示。本站沒有建案經緯度，捷運線索只以同路名篩選，不表示實際距離、通車時程或未來漲幅。沒有 LLM 摘要時仍會顯示資料摘要；頁面不會直接呼叫 LLM，也不會暴露 API 金鑰。

此頁另有 13 項「未來增值潛力評估」檢查表。第 1 項嫌惡設施及地質安全不做系統預判、不顯示預設狀態、也完全排除在分數外；頁面會持續提醒使用者自行確認，並保留個人紀錄選項。第 2–13 項依使用者優先順序設定為 18、12、9、9、8、8、8、7、6、5、5、5 分，合計 100 分。每個建案的回答只儲存在目前瀏覽器；分數一律顯示目前已確認條件的加權結果，同時呈現已查核權重與可能範圍，避免將未知項目偽裝成確定結果。這只是主觀條件的加權清單，**不是房價漲幅、報酬率或已由 AI 驗證的預測**；捷運同路段線索不會自動判定為符合。

## 判讀規則

1. 候選建案必須與目標建案類型相同，且定位快照的直線距離在 **0 至 300 公尺**，首次公開成交年份相差不超過使用者設定的 **1、2 或 3 年**。預售屋尚無實際屋齡，首次成交年份僅作為案齡代理值，並非完工年份。距離來自公開地理編碼的位置快照，地址可能被定位到路段或巷口；它是嚴格的初篩，不可取代基地圖、地籍圖或現場確認。
2. 只納入**不含車位的房屋坪數**相差不超過 25%、近三年內成交的案例，每個建案最多取最近 30 筆。候選清單把同一路名排在前面，也會列出符合條件的中和區其他路段建案。
3. 本案自己的近三年、相近坪數成交會自動納入。系統另預設選入可比建案中、各案成交單價中位數最低的最多 **3 個不同建案**；使用者可自行加入、移除或清空。只要本案或任一已加入建案有可用成交，即會亮燈；全部沒有可用成交才不判燈。先算每案成交單價中位數，再取各案中位數的中位數，讓每案只占一票。開價低於基準是綠燈；基準至高出 15% 是黃燈；高出超過 15% 是紅燈。

房屋坪數與開價都應排除車位。官方每坪單價使用資料中的單價欄位，並從元／平方公尺轉為萬／坪。此版沒有經緯度資料；同一路名不保證兩處基地相鄰。預售屋的公開成交資料有發布延遲，且成交中位數不是可保證的議價底價。

觀察列表的燈號與上方三案比較分開計算：以同一建案近三年交易單價的第 25 百分位作便宜界線、中位數作合理參考價、第 75 百分位作昂貴界線；最新一筆單價落在下四分位及以下為綠燈，上四分位及以上為紅燈，其餘為黃燈。少於 5 筆或最新交易已超過三年時不判燈。平均總價包含官方原始交易總價中的車位，平均房屋坪數則扣除車位，兩者不可直接相除當作每坪單價。

## 位置與周邊設施快照

`data/zhonghe-geo.json` 以使用者同意後查詢的 OpenStreetMap Nominatim 與 Overpass API 產生，收錄建案位置及 **0 至 300 公尺**內的捷運／車站、超市／便利商店、學校、公園、醫院、商場與宗教場所。更新時才會將建案地址交給 Nominatim；網頁只讀取本機快照，不會自行傳送地址或即時爬取。

```bash
python3 scripts/update-geo-data.py
```

13 項評估會對可由 POI 直接查核的捷運、民生採買、公園、商場及醫療資源自動預填「符合」或「不符合」；採光、車位、學區品質、物業、街廓、建商、公設及地質／淹水等不應只靠 POI 判定，因此一律預填「待查」。所有自動結果都可由使用者調整。OpenStreetMap 資料依 [ODbL](https://www.openstreetmap.org/copyright) 提供，並可能有缺漏或更新延遲。

`data/trend-evidence.json` 是通用的官方建設證據格式，而非捷運特例。每筆規劃／施工中的站點或基地可用 `criteria` 標記它影響的 1–13 項（例如 `[2]` 為捷運／軌道交通、`[7]` 為公園綠地）。只有同時具備官方來源、`規劃中`／`施工中`狀態、對應項目與可供 300 公尺初篩的座標時，該項才會自動預填「符合」，並顯示「規劃／施工中」與來源說明。沒有這些資料的項目不會被假設為符合。現有設施仍可由 OpenStreetMap 快照判定；規劃資料不是通車保證，也不可取代官方出入口圖與現場確認。
